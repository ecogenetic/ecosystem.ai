# Introduction

The ecosystem.Ai runtime serves **Model Context Protocol (MCP) natively** on the same base URL as `/invocations` and `/response`. There is no separate MCP container image.

- **`POST /mcp`** — JSON-RPC 2.0 (`tools/call`, `tools/list`, `prompts/list`, resources).
- **Streamable HTTP** — responses may be JSON or a per-request SSE stream; send `Accept: application/json, text/event-stream`.
- **Older clients** — `GET /mcp` + `POST /mcp/message` (deprecated HTTP+SSE); new clients should use `POST /mcp` only.
- **Auth** — mutating tools require `X-API-KEY` or `Authorization: Bearer {MASTER_KEY}` when `MASTER_KEY` is set.

Full reference: [MCP Support](/docs/runtime/mcp) in the current docs site.

## `/mcp`

```bash
curl -X POST "https://your-runtime-host/mcp" \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": {
      "name": "invoke",
      "arguments": {
        "campaign": "my_campaign",
        "subcampaign": "default",
        "customer": "customer-123",
        "channel": "app",
        "numberoffers": 3,
        "userid": "mcp-user",
        "params": "{}"
      }
    }
  }'
```

After `invoke`, close the loop with the `response` tool or `POST /response` using the returned `uuid` and `offer_name`. See [API Access](/docs/runtime/access).
